# 심야 병동 맵·멀티플레이 방 스펙

- 문서 버전: 1.6
- 기준일: 2026-07-28
- 상태: 서버 구현 기준
- 코드 기준점: `src/shared/map.ts`, `src/server/engine.ts`, `src/client/game/ThreeGameView.ts`

사용자 표시 명칭은 `혼자하기`·`친구랑하기`로 변경하고 내부 서버 모드 키 `single`·`multi`는 기존 전적 호환을 위해 유지한다. 별도 14일 시즌형 랭크전과 48시간 고정 시드 계약은 `docs/spec/ranked-mode.md`에서 정의한다.

## 1. 맵 토폴로지

- 맵 전체 크기는 39×25 타일이다. 8개 병실을 4×2 구획에 분산해, 방 사이의 불필요하게 넓은 복도를 줄인다.
- 방 외부의 모든 내부 빈 칸은 복도로 연결한다. 방 테두리·외곽벽 외의 장식용 단독 벽은 만들지 않아 터치 이동이 막히지 않는다.
- 방은 복도 사각 셀 안에 2행×4열, 총 8개를 생성한다. 배치 구획만 4×2일 뿐, 각 방은 바닥 20~27칸의 서로 다른 크기·형태를 하나씩 사용한다.
- 방의 문 방향은 상·하·좌·우 중 시드 기반으로 선택한다. 방 바닥과 복도 사이에는 문 한 칸만 통로로 남겨 벽 통과를 막는다.
- 플레이어·귀신 A\* 경로는 같은 `walkable` 타일 집합을 사용한다. 모든 방의 침대에서 리스폰 구역까지 문을 포함한 경로가 존재해야 맵을 승인한다.

## 2. 혼자하기 방

- 방 바닥은 최소 20칸, 최대 25칸이다.
- 4×5, 5×4, 5×5, 6×4와 모서리를 제거한 꺾인 형태를 섞는다.
- 방마다 침대 1개를 두고 나머지 19~24칸을 건설 가능 타일로 사용한다.
- 한 방에는 한 명만 머문다.

## 3. 친구랑하기 공유 방

- 모든 방은 정확히 25칸이다.
- 방마다 서로 떨어진 침대 2개를 두고 23칸을 건설 가능 타일로 사용한다.
- 한 방 최대 인원은 침대 수와 같은 2명이다. 생존자는 준비 시간 또는 전투 중 빈 침대 가까이에서 직접 점유하며, 서버가 시작 시점에 빈 침대를 자동 배정하지 않는다.
- 혼자하기는 방 정원을 정확히 1명으로 제한한다. 따라서 봇 또는 플레이어가 이미 점유한 혼자하기 방의 다른 침대 좌표에는 들어갈 수 없다. 친구랑하기에서만 같은 방의 서로 다른 침대 두 개를 사용한다.
- 같은 방의 두 플레이어는 빈 타일에 각각 건설할 수 있고, 누가 설치했는지와 관계없이 포탑·문·발전기 등 설비를 강화할 수 있다.
- 각 플레이어는 자기 침대만 강화할 수 있다.
- 침대 골드는 해당 침대 점유자에게만 지급한다.
- 발전기 전력은 `BuildingState.ownerId`와 플레이어 ID가 같은 발전기에서만 지급한다.
- 다른 플레이어가 설비를 강화해도 설치 소유자는 바뀌지 않으므로 생산 귀속도 바뀌지 않는다.
- 같은 방 플레이어는 설비를 철거할 수 있다. 서버는 설치·강화 때마다 플레이어별 투자 골드와 전력을 기록하고, 철거 시 총 투자액의 70%를 각 투자자에게 분배한다.
- 철거된 `BuildingState`는 서버 스냅샷에서 제거되며 해당 타일은 즉시 다시 건설할 수 있는 빈 타일이 된다.

## 4. 대기실 방 수명주기와 권한

- 모든 플레이어는 대기실에서 `방 나가기`를 사용할 수 있다. 명시적 퇴장은 네트워크 단절과 다르게 처리하며 해당 플레이어의 재접속 토큰을 폐기한다.
- 방 나가기, 추방, 빈 방 종료 후에는 구형 플레이 방식 선택 화면을 거치지 않고 게임 홈으로 돌아간다.
- 혼자하기는 서버 연결용 내부 방 식별자를 사용하되 대기실에 `ROOM CODE`를 표시하거나 복사 기능을 제공하지 않는다. 초대 코드는 친구랑하기에서만 노출한다.
- 방장이 나가고 다른 실제 플레이어가 있으면 연결된 실제 플레이어 중 먼저 입장한 사람이 새 방장이 된다. 이전 방장은 자동 복귀하지 않으며 초대 코드를 다시 입력해야 참가할 수 있다.
- 마지막 실제 플레이어가 나가면 남아 있던 봇을 함께 제거하고 Durable Object 방 상태·알람을 삭제한다. 이후 사용자는 새 방을 만들 수 있다.
- 방장만 대기실의 봇을 제거하거나 다른 실제 플레이어를 추방할 수 있다. 추방된 플레이어의 재접속 토큰도 즉시 폐기한다.
- 봇 제거·추방·방장 승계 결과는 서버 스냅샷으로 모든 남은 참가자에게 동기화한다.

## 5. 귀신 목표 선택

- 방을 점유하지 못한 연결된 생존자가 한 명이라도 있으면 귀신은 문보다 해당 생존자를 우선 추적한다. 실제 플레이어를 봇보다 먼저 선택하고, 같은 유형 안에서는 귀신과 가까운 생존자를 선택한다.
- 이 복도 추적 중 귀신 이동속도는 기본·스테이지·변종·격노·감속 보정 뒤에 `1.35배`를 적용하되, 실제 대상 생존자의 현재 이동속도보다 최소 `1.5배` 빠르게 보장한다. 생존자 현재 속도에는 등급, 캐릭터·스킨 특성, 임시 이동속도 강화가 포함된다. 느린 귀신이나 서리 감속 상태에서도 이 하한보다 느려지지 않아 준비 시간 이후 복도 도주만으로 전투를 무기한 지연할 수 없다. 접촉 공격은 한 번에 사망 처리한다.
- HP가 20% 이하가 된 귀신은 후퇴 중인 수호 포탑 집중 사격 피해를 1.45배만 받고, 기본 이동 보정의 1.30배로 현재 위치에서 가장 가까운 리스폰 패드까지 이동한다. 패드는 네 모퉁이와 상·하·좌·우 변 중앙에 하나씩, 총 8개다.
- 미점유 생존자가 없을 때만 귀신은 살아 있는 플레이어가 있는 방을 목표 후보로 사용한다.
- 목표가 필요할 때 후보 중 하나를 균등 무작위로 선택하며 첫 방이나 최근 방을 고정 우선하지 않는다.
- 쌍둥이 귀신은 후보 방이 2개 이상이면 다른 쌍둥이가 선택한 방을 제외하고 고른다.
- 목표 방의 문이 살아 있으면 문을 공격하고, 문이 파괴되면 그 방의 살아 있는 플레이어 중 가까운 플레이어를 공격한다.

## 6. 렌더링·조작

- 복도 판정은 단일 가로 띠가 아니라 `corridorTiles` 전체를 사용한다.
- 복도망 전체에 샘플 조명을 분산한다.
- 벽 높이는 본체 0.68, 상단 캡 0.73 유닛으로 제한한다.
- 방 정원은 침대 `점유` 권한에만 적용하고 이동 충돌 지형에는 적용하지 않는다. 다른 생존자가 방을 점유해도 문·방 바닥의 이동 가능 여부를 바꾸지 않으며, 미점유 생존자는 그 방을 통과할 수 있지만 침대를 점유할 수는 없다.
- 봇의 방 점유로 플레이어를 문 밖으로 순간이동시키거나 현재 이동 입력을 정지하지 않는다. 서버와 클라이언트 모두 정적인 맵 벽만 이동 충돌에 사용해 점유 스냅샷 직후 앞뒤 보정 진동이 생기지 않게 한다.
- 다른 봇의 점유처럼 플레이어 좌표가 전진하지 않은 액션 스냅샷이 끼어들어도, 드래그 입력 방향의 반대로 로컬 캐릭터를 보정하지 않는다. 예측 허용 거리에 도달하면 서버 이동 스냅샷이 따라올 때까지 그 자리에서 기다려 방 안의 벽 근처에서도 앞뒤 진동이 발생하지 않게 한다.
- 생존자 HUD 초상화는 닉네임·캐릭터·프로필 사진이 바뀔 때만 다시 만든다. `roomId` 변경은 초상화의 시각 정보가 아니므로 봇이 방을 점유할 때 이미지 DOM을 재생성하거나 디코딩하지 않는다.
- 방 안의 모든 침대는 독립 모델로 표시하고 선택 ID는 `bed:{roomId}:{bedIndex}`를 사용한다.
- 잠자기 버튼과 서버 점유 판정은 침대 거리뿐 아니라 플레이어가 해당 방 바닥 위에 있는지도 확인한다. 벽 바깥·복도 모서리에서는 침대를 점유할 수 없다.
- 카메라는 점유 전 살아 있는 플레이어를 추적하고 점유 후 드래그와 0.5×~1.5× 확대/축소를 허용한다. 북쪽이 화면 위인 수직 시점을 고정하고 회전은 제공하지 않는다. 사망 뒤에는 즉시 추적을 해제해 관전 카메라를 드래그·확대/축소할 수 있다.
- 설치·강화 패널 바깥을 누르면 패널과 선택 상태를 닫는다. 별도 취소 버튼은 두지 않는다.

## 7. 검증 조건

- 동일 시드는 동일 맵을 만든다.
- 방 8개와 리스폰 패드 8개가 생성되고, 모드별 침대 수가 일치한다.
- 모든 이동 가능 타일이 하나의 연결 성분이다.
- 각 방의 침대→플레이어 스폰 경로는 해당 방 문을 반드시 지난다.
- 친구랑하기 두 명이 같은 방의 다른 침대에 배정되고, 공동 강화와 개인 생산 귀속이 서버 테스트로 검증된다.
- 랭크전의 같은 계약 ID는 모든 참가자에게 동일한 맵 시드를 사용한다.
- 쌍둥이는 서로 다른 점유 방이 존재할 때 서로 다른 목표를 선택한다.
- 방장 퇴장 후 승계, 봇 제거, 플레이어 추방, 마지막 사람 퇴장 후 방 삭제가 실제 WebSocket 두 클라이언트 시나리오에서 검증된다.
- 설치·강화 투자액의 70% 환급과 같은 타일 재건설이 서버 테스트로 검증된다.
- 혼자하기 봇 3명이 차례로 서로 다른 방을 점유하는 동안에도 이동 중인 실제 플레이어의 서버 좌표가 비정상적으로 이동하지 않아야 한다.
- 실제 플레이어가 복도 또는 방 A를 이동하는 동안 봇이 서로 다른 방 B를 점유해도 플레이어의 속도와 진행 방향이 유지되어야 한다.
- 같은 시나리오의 실제 렌더링 회귀 테스트에서 연속 프레임의 최대 시각 이동량은 0.34타일 미만, 서버 좌표와 렌더 좌표의 오차는 0.9타일 미만이어야 한다.
- 방 안 이동 중 다른 방의 봇 점유 액션이 이전 플레이어 좌표를 반복해도, 누르고 있는 이동 방향의 반대로 렌더 좌표가 한 프레임도 후퇴하지 않아야 한다.
- 미니미가 방의 마지막 생존자를 처치하면 언데드 본체와 다른 미니미도 해당 방·플레이어 목표를 즉시 폐기하고, 남은 생존자의 방으로 다시 경로를 탐색해야 한다.
