# 귀신 술래잡기 미니게임 기획

- 문서 버전: 0.9
- 기준일: 2026-08-04
- 상태: 정식 출시 범위 구현
- 가칭: `심야 술래잡기`
- 관련 문서: `map-multiplayer.md`, `social.md`, `visual-design.md`

## 1. 모드 목표

`심야 술래잡기`는 기존의 방 점유·건설·방어 전투와 분리된 비대칭 추격 미니게임이다. 한 명은 랜턴을 든 귀신이 되고, 최대 여섯 명의 생존자는 어두운 병동에서 열쇠를 하나씩 운반해 탈출구 자물쇠 5개를 해제하면 팀 승리한다.

핵심 재미는 다음 세 가지다.

1. 랜턴 불빛이 닿기 직전까지 숨어 이동하는 긴장감
2. 팀이 탐색한 지형과 번호 위치를 공유하는 협동
3. 실제 플레이어가 귀신 역할을 맡아 추적하는 심리전

기존 캐릭터·스킨은 생존자 외형에 그대로 적용한다. 등급·캐릭터·스킨의 이동속도 보너스와 전투 능력은 이 모드에서 비활성화해 경쟁 조건을 동일하게 맞춘다.
귀신은 `랜턴 귀신` 외형을 새로 제작한다. 귀신 외형은 기본적으로 플레이어의 캐릭터보다 크고 어두운 색상을 사용한다. 얼굴은 wallpaper 이미지와 비슷한 느낌을 주게 제작한다.

### 1.1 0.7 구현 범위

현재 버전은 홈의 플레이 방식 선택에서 실제 방을 만들고 초대 코드로 입장해 한 경기를 진행할 수 있는 첫 수직 슬라이스다.

- 구현 완료: 84×60 시드 맵, 전용 `HideSeekRoom`, 역할·번호 배정, 20초 숨기, 7분 30초 추격, 랜턴 발견, 연속 접촉 사망, 달리기, 완전 은신처, 열쇠 5개, 다섯 번째 자물쇠 즉시 승리, 결과 판정
- 구현 완료: 기존 생존자 스킨 렌더링, 위협적인 전용 랜턴 귀신 4방향 이동 모션, 고정 카메라, 360도 랜턴 시야와 불켜기, 역할별 탐험 미니맵, 네 가지 빠른 문구, 역할별 정보 비공개, 재접속과 일반 연결 이탈의 봇 인계
- 구현 완료: 일반 게임과 동일한 설정·이동 드래그·팀 채팅·우측 액션 버튼 구조, 설정창을 통한 게임 이탈, 인게임 BGM 전환
- 구현 완료: 바닥·벽·사물함·도구함·침대·열쇠·잠긴/열린 탈출구 전용 투명 배경 아트와 근접 상황형 상호작용 버튼
- 구현 완료: 일반 대기실과 같은 고정 하단 액션 구조, 스크롤 참가자 목록, 계정 등급 배지와 모바일 7인 표시
- 구현 완료: 방장 봇 한 명 추가·빈자리 일괄 보충, 봇 경로 탐색과 탐험·열쇠·도주·추격 판단
- 구현 완료: 대기 중인 공개 방을 무작위로 찾고 빈방이 없으면 새 방을 만드는 빠른 참가, 술래·마지막 생존자의 명시적 탈주에 따른 즉시 승패 처리
- 구현 완료: 사망 알림, 살아 있는 생존자 번호별 관전 카메라, 승리 역할별 포인트와 일반 경기와 동일한 광고 2배 수령
- 구현 완료: 귀신 전용 격리 대기실, 숨기 시간 내부 이동, 추격 시작 시 출입문 개방, 생존자 영구 출입 제한
- 구현 완료: 구조물 위치에 뜨는 은신·수색 월드 버튼, 은신 중 구조물과 앞 한 칸을 함께 보여주는 제한 시야
- 구현 완료: DB 노출·순서 제어가 가능한 출시 팝업과 홈 플레이 방식·술래잡기 항목을 잇는 2단계 안내 화살표
- 안정화 완료: 백그라운드 복귀 시 최신 토큰으로 기존 역할에 재접속하고, 서버·클라이언트가 동일한 축 슬라이딩으로 벽면 이동을 예측
- 안정화 완료: 로컬 이동은 프레임 단위로 이어가고 큰 서버 오차만 부드럽게 보정해 일반 이동과 카메라의 스냅샷 되감김을 방지
- 조작 개선: 열쇠는 근접 버튼을 한 번 누르면 즉시 획득하고, 이동 포인터를 유지한 상태에서도 두 번째 터치로 달리기·불켜기 사용 가능
- 탈출 규칙 개선: 생존자 한 명이 열쇠 하나만 운반하고, 출구에서 열쇠를 하나씩 소비해 자물쇠 5개를 순서대로 해제하며, 사망한 운반자의 열쇠와 위치를 생존자 팀에 공유
- 봇 안정화: 열쇠를 운반한 생존자 봇은 탈출구 상호작용이 끝날 때까지 이동을 멈추고 자물쇠를 정상적으로 해제하며, 다섯 번째 해제 즉시 생존자 승리로 종료
- 긴장감 개선: 술래와 생존자가 6타일 안으로 접근하면 양쪽에 노란 느낌표를 표시하고, 생존자에게 거리에 따라 커지고 빨라지는 술래 발소리를 재생
- 최적화 완료: 20Hz 서버 판정·10Hz 역할별 스냅샷, 탐험 영역 비트셋 압축, 로컬 프레임 적분·원격 최대 0.12초 예측, 모바일 캔버스 DPR 상한
- 다음 단계: 접속 중 사용자 무작위 초대, 친구 초대 알림, 소리·지름길·출구 캠핑 방지의 고급 규칙, 경기 통계·미션 정산

기획서 아래의 규칙 중 구현 범위에 포함되지 않은 항목은 삭제한 것이 아니라 다음 단계의 기준으로 유지한다. 운영 배포 전에는 7개 동시 클라이언트 부하와 iOS·Android 실기기 입력을 추가 검증한다.

## 2. 참가 인원과 번호

- 한 경기 최대 인원은 `귀신 1명 + 생존자 6명`, 총 7명이다.
- 권장 시작 인원은 귀신 1명과 생존자 4~6명이다.
- 최소 시작 인원은 귀신 1명과 생존자 2명이다. 빈 자리는 봇으로 보충할 수 있다.
- 생존자는 입장 순서와 무관하게 경기 시작 때 무작위로 `1~6번`을 배정한다.
- 귀신은 서버 판정상 항상 `0번`이지만, 게임 화면과 미니맵에는 번호를 노출하지 않는다.
- 생존자에게는 `당신은 3번입니다.`처럼 표시하고, 귀신에게는 `당신은 술래입니다.`만 표시한다.
- 게임 화면과 미니맵에서는 닉네임 대신 번호만 사용한다. 대기실과 결과 화면에서는 닉네임을 다시 표시한다.

번호를 매 경기 무작위로 배정하면 특정 친구가 계속 미끼 역할로 지목되는 문제를 줄이고, 귀신이 닉네임만 보고 특정 사용자를 집중 추적하는 행위도 완화할 수 있다.

## 3. 진입 방식

### 3.1 방 만들기와 초대 코드

- 홈의 플레이 방식에 `술래잡기`를 추가한다.
- `방 만들기`, `초대 코드로 참가`, `빠른 참가`를 제공한다.
- 초대 코드는 기존 친구랑하기와 같은 8자리 형식을 사용한다.
- 방장은 공개 여부, 봇 자동 보충 여부, 귀신 역할 배정 방식을 설정한다.
- 방장은 실제 플레이어와 봇을 추방할 수 있고, 방장이 나가면 먼저 입장한 실제 플레이어에게 권한을 승계한다.

### 3.2 접속 중인 사용자 무작위 초대

- 방장은 `접속 중인 생존자 초대` 버튼으로 현재 게임 중이 아니며 무작위 초대 수신을 허용한 사용자 10~20명에게 한 번에 초대를 보낼 수 있다.
- 초기 기본값은 15명이다. 방 정원이 먼저 차면 남은 초대는 자동으로 만료 처리한다.
- 후보는 `홈`, `상점`, `이벤트`, `대기실이 아닌 메뉴 화면`에 있는 사용자만 포함한다.
- 이미 다른 대기열·대기실에 있거나 게임 중인 사용자는 제외한다.
- 무작위 초대는 60초 뒤 만료하고, 일반 친구 초대는 기존 규칙과 맞춰 5분 동안 유지한다.
- 같은 방의 무작위 초대는 30초에 한 번만 보낼 수 있다.
- 한 사용자가 받는 무작위 초대는 5분에 최대 3개로 제한한다.
- 설정에 `무작위 술래잡기 초대 받기`를 두고 기본값은 켜짐으로 하되, 알림을 한 번 거절하면 같은 방에서는 다시 보내지 않는다.
- 차단한 사용자, 최근 함께 플레이하지 않기로 선택한 사용자, 신고 제재 중인 사용자는 후보에서 제외한다.

### 3.3 빠른 대기열과 봇 보충

- `빠른 참가`는 현재 대기 중이며 실제 사용자가 참가할 수 있는 공개 방을 무작위로 하나 선택한다.
- 대기실이 봇으로 가득 찬 경우 실제 사용자가 들어오면 봇 한 명을 내보내고 자리를 넘긴다.
- 참가 가능한 방이 없으면 새 방을 만든 뒤 `현재 입장 가능한 방이 없어 새로운 방을 생성합니다.`를 안내한다.
- 대기열 입장 시 `귀신 희망`, `생존자 희망`, `상관없음` 중 하나를 선택한다.
- 첫 25초는 실제 플레이어를 우선 탐색한다.
- 25초부터 방장에게 `봇으로 시작` 버튼을 활성화한다.
- 자동 보충을 켠 방은 45초가 지나면 최소 인원을 봇으로 채워 시작할 수 있다.
- 실제 플레이어가 한 명뿐이어도 그 사용자가 원하면 귀신 봇 1명과 생존자 봇을 추가해 연습 경기를 시작할 수 있다.
- 공개 대기열은 권장 인원인 생존자 4명 이상을 먼저 목표로 하고, 대기 시간이 길어질 때만 최소 인원까지 낮춘다.

## 4. 귀신 역할 배정

- 귀신 희망자가 한 명이면 그 사용자가 귀신이 된다.
- 귀신 희망자가 여러 명이면 최근 5경기에서 귀신을 맡은 횟수가 적은 사람에게 높은 확률을 주는 가중 무작위로 정한다.
- 귀신 희망자가 없으면 `상관없음` 참가자 중에서 정한다.
- 모두 생존자만 희망했고 봇 사용이 허용되어 있으면 귀신 봇을 배정한다.
- 봇 사용이 꺼져 있으면 한 명이 귀신 역할을 선택할 때까지 시작할 수 없다.
- 역할 확정 후 5초 동안 역할 카드와 조작법을 표시한다.

사람이 귀신을 맡았을 때는 술래잡기 전용 `랜턴 귀신` 외형을 사용한다. 계정의 생존자 캐릭터·스킨은 생존자 역할에서만 적용한다. 이후 랜턴 귀신 전용 스킨을 별도 꾸미기 상품으로 확장할 수 있지만, 랜턴 범위와 충돌 크기는 모든 외형에서 동일해야 한다.

## 5. 경기 단계와 시간

권장 한 경기 길이는 준비를 포함해 최대 7분 55초다.

| 단계 | 시간 | 규칙 |
| --- | ---: | --- |
| 역할 안내 | 5초 | 0~6번과 역할 표시, 이동 잠금 |
| 숨기 | 20초 | 생존자는 맵에서 이동, 귀신은 잠긴 격리 대기실 내부에서만 이동 |
| 추격 | 7분 30초 | 열쇠 운반, 자물쇠 순차 해제, 탐색, 추격 진행 |
| 결과 | 10초 이상 | 생존·탈출·발견·추격 결과와 보상 표시 |

- 숨기 단계에서 귀신은 불투명 철문이 닫힌 별도 격리 대기실에 배치한다. 방 내부에서는 자유롭게 이동하지만 문을 통과하거나 방 밖을 볼 수 없다.
- 숨기 단계가 끝나면 철문이 열리고 귀신은 복도로 나갈 수 있다. 생존자는 경기 내내 귀신 대기실과 문 타일에 진입할 수 없다.
- 추격 시간이 끝날 때까지 자물쇠 5개를 모두 해제하지 못하면 귀신 팀 승리다.
- 다섯 번째 자물쇠가 해제되면 생존자 전원의 위치·생존 여부와 관계없이 즉시 생존자 팀 승리다.
- 모든 생존자가 사망하면 즉시 귀신 팀 승리로 결과 단계에 진입한다.
- 활성 탈출로 좌표와 네 개의 후보 좌표는 술래 클라이언트에 전송하지 않는다. 술래는 생존자를 직접 추적하는 과정에서만 출구 주변을 추론할 수 있다.
- 술래가 설정의 나가기를 두 번 눌러 명시적으로 탈주하면 즉시 `술래가 게임을 탈주하였습니다.`와 `생존자 승리!`를 표시한다.
- 사망·탈출하지 않은 생존자가 한 명만 남은 상태에서 그 생존자가 명시적으로 탈주하면 즉시 `생존자가 게임을 탈주하였습니다.`와 `술래 승리!`를 표시한다.
- 일시적인 네트워크 단절이나 앱 백그라운드 전환은 탈주로 판정하지 않고 기존 봇 인계·재접속 유예를 유지한다.

## 6. 맵 구조

### 6.1 권장 크기

- 초기 맵 크기는 `84×60 타일`을 사용한다. 현재 일반 모드 39×25보다 약 5.2배 넓다.
- 세로 모바일 화면의 고정 카메라에서 한 번에 약 11×18타일이 보이도록 한다.
- 맵 한쪽 끝에서 반대편까지 기본 속도로 이동하는 최장 경로는 45~55초 안에 들어오도록 제한한다.
- 맵은 매 경기 시드 기반으로 생성하되, 구역의 성격과 주요 순환로는 유지한다.

### 6.2 구역 구성

한 맵은 다음 일곱 구역을 연결한다.

1. `중앙 접수 구역`: 넓고 밝기 대비가 큰 중앙 기준점과 보안 접수대
2. `폐쇄 병동`: 벽으로 구분된 병실·철제 침대·커튼이 많은 은신 구역
3. `병동 카운터`: 곡선 간호 스테이션과 의료 장비가 있는 길찾기 기준점
4. `수술실`: 수술대와 조명 장치가 놓인 긴 시야의 고위험 구역
5. `세탁·격리실`: 카트와 세탁물 사이의 짧은 시야 차단 구간
6. `의무기록 보관실`: 좁은 서가와 여러 갈림길이 있는 미로형 구역
7. `지하 정비 구역`: 파이프와 기계 설비가 있는 어두운 우회 구역

### 6.3 생성 규칙

- 외곽 대순환로 1개와 내부 순환로 2개 이상을 만든다.
- 모든 주요 구역은 서로 다른 두 개 이상의 출입구를 가진다.
- 6타일보다 긴 막다른 길은 만들지 않는다. 막다른 길에는 반드시 은신처 또는 지름길을 둔다.
- 교차로는 평균 6~8타일마다 하나씩 배치한다.
- 귀신이 한 지점만 지켜 전체 진행을 막지 못하도록 열쇠 생성 지점 18개와 탈출구 후보 4개를 넓게 분산한다.
- 귀신 시작점과 생존자 시작점 사이의 최단거리는 12타일 이상으로 한다.
- 생존자는 3개의 시작 구역에 나뉘어 배치하고, 같은 위치에 겹쳐 생성하지 않는다.

## 7. 은신 공간과 심리전

맵에는 48개의 은신 수단을 두어 대형 맵에서도 이동 경로마다 여러 선택지가 생기게 한다.

### 7.1 완전 은신처

- 1인 사물함, 대형 2인 철제 사물함, 청소 도구함, 침대 밑 공간, 세탁 햄퍼, U자형 병실 커튼을 사용한다.
- 한 곳에는 한 명만 들어갈 수 있다.
- 내부에 있으면 랜턴 감지에서 제외된다.
- 내부에 있는 생존자의 화면은 구조물 앞 통로 한 칸만 남기고 암전한다.
- 귀신은 0.8타일 이내에서 `수색` 버튼을 한 번 누르면 2초 자동 탐색이 시작된다. 버튼에는 남은 시간이 표시되며 거리를 벗어나면 취소된다.
- `숨기`와 `수색`은 하단 고정 액션을 바꾸지 않고 일반 모드의 줍기·잠자기처럼 해당 구조물 위에 상황형 버튼으로 표시한다.
- 점유 중이면 수색 완료 즉시 사망한다.
- 12초 이상 숨어 있으면 작은 숨소리나 문 떨림이 3타일 이내 귀신에게 들린다. 강제로 내보내지는 않는다.
- 들어가거나 나올 때 2타일 범위의 소음을 만든다.

### 7.2 부분 은신처

- 병실 커튼, 뒤집힌 카트, 큰 약품장, 기둥 그림자를 사용한다.
- 캐릭터는 물리적으로 이동한 상태를 유지하고 랜턴의 직선 시야만 차단한다.
- 귀신이 0.8타일 이내로 접근하면 주변 약한 빛으로 실루엣이 보인다.
- 수색 버튼 없이 몸이 닿으면 즉시 사망한다.

### 7.3 생존자 전용 지름길

- 환풍구, 낮은 배관, 무너진 벽 틈을 4~6곳 배치한다.
- 생존자는 1초의 통과 모션 뒤 반대편으로 이동한다.
- 귀신은 사용할 수 없지만, 사용 소리가 5타일 안에 들린다.
- 같은 지름길은 한 생존자가 20초 동안 다시 사용할 수 없어 무한 순환 도주를 막는다.

## 8. 암전과 랜턴

- 전체 맵은 거의 암전된 병원 복도 분위기로 표현한다.
- 생존자는 반경 2타일까지 명확히 보고 4타일까지 부드럽게 감쇠한다. 그 밖의 맵은 12% 밝기의 윤곽만 보여 길 전체를 미리 읽지 못하게 한다. 이것은 귀신 발견 판정에 영향을 주지 않는다.
- 귀신은 방향과 무관하게 주변 360도, 반경 2타일을 기본 랜턴 시야로 밝힌다.
- 귀신의 기본광 바깥은 18% 밝기의 지형 윤곽을 남겨 완전한 검은 화면에서 길을 잃지 않게 한다. 생존자 위치 데이터는 발견 전까지 서버가 보내지 않으므로 지형을 밝히더라도 은신 위치가 노출되지는 않는다.
- 기본 랜턴 발견 판정은 정확히 2타일까지 적용한다.
- 벽, 닫힌 문, 완전 은신처는 랜턴 시야를 차단한다.
- 부분 은신처는 실제 렌더링과 동일한 가림 판정을 사용한다.
- 귀신의 마지막 이동 방향은 4방향 이동 모션을 선택할 때만 사용하며 기본 시야 판정에는 영향을 주지 않는다.

### 불켜기

- 귀신은 추격 중 `불켜기`를 사용할 수 있다.
- 사용 즉시 귀신 중심 반경 7타일이 전방위로 밝아지고, 4초 동안 서서히 어두워진다.
- 밝아진 영역은 범위 안 생존자의 화면에도 동일하게 표현되므로 귀신 위치를 드러내는 위험이 있다.
- 재사용 대기시간은 발동 시점부터 100초다.
- 벽과 완전 은신처는 확장 시야의 발견 판정을 차단한다.

### 8.1 발견 표식

- 생존자가 기본 랜턴의 360도 반경 2타일 또는 활성화된 불켜기의 반경 7타일 안에 있고 가려지지 않았다면 발견 상태가 된다.
- 발견 순간 귀신과 해당 생존자의 머리 위에 빨간색 `!`를 표시한다.
- 발견 뒤에는 시야가 벽에 가려져도 귀신과 생존자 사이의 거리가 4타일 이내면 표식을 유지한다.
- 거리가 4타일을 벗어난 상태가 0.4초 이상 이어지면 두 표식을 함께 제거한다.
- 4타일 경계에서 서버 좌표가 흔들려 표식이 깜빡이지 않도록 해제 지연을 둔다.
- 생존자는 귀신이 본인 기준 2타일 안에 들어오고 벽에 가리지 않았을 때 미니맵에서 귀신을 빨간색으로 확인한다. 범위를 벗어나면 즉시 정확한 위치를 숨긴다.

### 8.2 근접 경고와 발소리

- 술래와 살아 있는 생존자의 거리가 6타일 이내가 되면 각자의 화면과 캐릭터 머리 위에 노란색 `!`를 표시한다.
- 빨간 발견 표식과 조건이 겹치면 빨간 표식을 우선 표시한다.
- 생존자는 6타일 경계에서 작은 술래 발소리를 듣고, 거리가 가까워질수록 음량이 커지고 반복 간격이 짧아진다.
- 완전 은신처 안에서도 생존자는 근접 발소리를 들을 수 있다. 반대로 술래에게는 은신 중인 생존자로 인한 노란 표식을 제공하지 않아 점유된 은신처를 역추적할 수 없게 한다.
- 발소리는 효과음 음소거·효과음 볼륨·앱 백그라운드 상태를 따르며, 별도 파일 다운로드 없이 짧은 합성음으로 재생해 모바일 네트워크와 메모리 부하를 늘리지 않는다.

## 9. 이동, 달리기, 접촉 판정

### 9.1 공통 이동

- 귀신과 모든 생존자의 일반 이동속도는 기존 게임의 기본 속도 `1.0배`로 고정한다.
- 일반 등급, 랭크, 캐릭터 특성, 스킨 효과, 보급품의 이동속도 보정은 적용하지 않는다.
- 외형별 충돌 크기도 동일하게 정규화한다.
- 카메라는 북쪽이 위인 고정 수직 시점이며 확대·축소 버튼을 표시하지 않는다.
- 서버가 이동과 충돌을 최종 판정한다. 클라이언트는 프레임 경과 시간 기반 보간과 다음 스냅샷까지 최대 0.12초의 짧은 이동 예측을 사용해 10Hz 위치 갱신 사이의 정지를 감춘다.

### 9.2 귀신 달리기

- 우측 하단에 기존 수리 버튼과 같은 크기의 `달리기` 버튼을 표시한다.
- 사용 시 5초 동안 `1.3배`로 이동한다.
- 사용 종료부터 60초의 쿨타임을 적용한다.
- 숨기 단계에는 사용할 수 없고 추격 시작 10초 뒤부터 첫 사용이 가능하다.
- 버튼에 남은 쿨타임 숫자와 원형 게이지를 함께 표시한다.

### 9.3 생존자 달리기

- 생존자도 우측 하단에 `달리기` 버튼을 가진다.
- 초기 권장값은 4초 동안 `1.2배`, 24초 쿨타임이다.
- 달리는 동안 발소리 감지 범위가 2타일에서 5타일로 늘어난다.
- 귀신의 발견 반경 4타일을 벗어나는 핵심 수단이지만, 소리 때문에 무조건 안전한 탈출은 되지 않는다.

### 9.4 사망 판정

- 귀신과 은신하지 않은 생존자의 충돌 반경이 닿으면 공격 모션이나 추가 입력 없이 즉시 사망한다.
- 빠른 이동 중 서로 통과하는 문제를 막기 위해 서버는 이전 위치와 현재 위치 사이의 선분까지 포함한 연속 충돌 판정을 사용한다.
- 네트워크 지연 보정은 최대 150ms까지만 인정해 과거 위치에서 지나치게 늦게 잡히는 상황을 제한한다.
- 사망한 본인에게는 `당신은 사망하였습니다`를 2초간 표시하고 이동·달리기·채팅·상호작용 버튼을 모두 제거한다.
- 다른 참가자에게는 `n번이 사망하였습니다`를 2초간 표시한다.
- 생존자를 잡은 귀신에게는 `생존자를 잡았습니다`를 2초간 표시한다.
- 사망자는 가장 낮은 번호의 생존자 카메라로 자동 전환하며, 하단에 가로로 나열된 생존자 번호 버튼으로 관전 대상을 바꿀 수 있다.
- 사망한 생존자가 열쇠를 운반 중이었다면 그 열쇠를 정확한 사망 위치에 떨어뜨린다.

## 10. 미니맵과 팀 정보

- 생존자는 팀 공유 미니맵을 사용하고, 귀신은 본인이 직접 탐험한 구역만 보이는 별도 미니맵을 사용한다. 귀신에게 채팅 버튼은 표시하지 않는다.
- 처음에는 모든 타일을 숨기고, 본인 또는 다른 생존자가 탐험한 방·복도만 팀 전체에 공유한다.
- 살아 있는 생존자의 현재 위치를 `1~6` 숫자로 표시한다.
- 본인은 노란색, 다른 생존자는 청록색으로 구분한다.
- 사망한 생존자의 마지막 위치는 번호가 포함된 회색 사망 표식으로 남겨 생존자 팀 미니맵에 공유한다. 귀신 미니맵에는 이 표식을 노출하지 않는다.
- 다섯 번째 자물쇠가 해제되면 미니맵과 상단 상태 목록을 더 갱신하지 않고 결과 화면으로 전환한다.
- 발견한 열쇠 위치와 탈출구 위치는 팀 공유 정보로 저장한다.
- 아직 줍지 않은 열쇠는 실제로 본 생존자가 있거나 `열쇠 발견!` 핑을 보낸 뒤에만 표시한다.
- 귀신 위치는 생존자 미니맵에 지속 표시하지 않고, 각 생존자와 2타일 이내일 때만 빨간색으로 표시한다.
- 재접속한 생존자는 서버에 저장된 팀 탐험 영역을 다시 받아 복원한다.

탐험 데이터는 타일 단위 비트셋으로 전송하고 변화분만 갱신한다. 전체 맵 좌표를 매 틱 다시 보내지 않는다.

## 11. 채팅과 빠른 문구

- 채팅 버튼은 생존자에게만 표시한다.
- 귀신 클라이언트에는 채팅 송신 UI를 만들지 않고, 서버도 생존자 채팅 이벤트를 귀신 소켓으로 전달하지 않는다.
- 생존자 자유 채팅은 기존 80자 제한과 전송 제한을 재사용한다.
- 빠른 문구는 아래 네 개만 제공한다.

1. `귀신 발견!`
2. `열쇠 발견!`
3. `탈출로 발견!`
4. `도망쳐!`

- 빠른 문구는 발신자의 번호와 함께 `3번: 열쇠 발견!`처럼 표시한다.
- 각 문구는 발신자 위치에 서로 다른 모양의 핑을 4초 동안 남긴다.
- 귀신은 말풍선, 채팅 기록, 핑을 모두 볼 수 없다.
- 사망한 생존자는 관전 중 채팅을 읽을 수 있지만 살아 있는 생존자에게 새 메시지를 보내지는 못한다. 사망자가 귀신 위치를 계속 중계하는 문제를 막기 위한 규칙이다.

## 12. 열쇠와 탈출

### 12.1 열쇠 생성

- 열쇠는 생존자가 직접 운반해 탈출구로 가져가는 개별 운반 자원이다.
- 한 생존자는 동시에 열쇠를 하나만 운반할 수 있다. 열쇠를 가진 생존자는 다른 열쇠를 주울 수 없다.
- 추격 시작과 동시에 첫 열쇠를 생성하고, 이후 50초마다 하나씩 생성한다.
- 다섯 번째 열쇠는 추격 시작 후 3분 20초에 생성되어 남은 시간 동안 탈출 기회를 보장한다.
- 줍지 않은 열쇠가 있어도 다음 열쇠는 예정대로 생성한다.
- 열쇠 생성 지점은 귀신과 6타일 이상, 생존자 시작 지점과 4타일 이상 떨어진 유효 타일만 사용한다.
- 같은 구역에 연속으로 두 개를 생성하지 않는다.
- 생존자가 지상 열쇠 근처의 `열쇠 줍기` 버튼을 한 번 누르면 즉시 운반 상태가 된다.
- 열쇠를 운반한 생존자가 사망하면 열쇠는 사망한 위치에 다시 나타나며 다른 생존자가 주울 수 있다.
- 통신 단절로 봇이 제어권을 넘겨받거나 같은 참가자가 재접속해도 운반 중인 열쇠는 해당 참가자 슬롯에 유지한다.
- 생성 순간에는 정확한 위치 대신 `의무기록 보관실에서 금속 소리가 들립니다.`처럼 구역 힌트만 생존자에게 표시한다.

### 12.2 탈출구

- 맵 생성 때 외곽의 탈출구 후보 4개 중 1개를 활성 탈출구로 정한다.
- 탈출구는 처음부터 존재하지만 탐험하기 전에는 미니맵에 표시하지 않는다.
- 생존자가 발견하거나 `탈출로 발견!`을 사용하면 팀 미니맵에 공유한다.
- 열쇠를 운반한 생존자가 탈출구에서 3초 동안 잠금 해제를 유지하면 열쇠 하나를 소비하고 자물쇠 하나를 해제한다.
- 잠금 해제 중 이동하거나 사망하면 진행이 취소되고 열쇠는 소비되지 않는다. 같은 생존자나 다른 열쇠 운반자가 다시 시도할 수 있다.
- 서로 다른 열쇠 5개로 자물쇠를 총 5회 해제해야 한다. 자물쇠 진행도는 팀 전체에 `3/5`처럼 공유한다.
- 자물쇠를 하나 해제할 때마다 모든 참가자 화면 중앙에 `n번째 자물쇠가 해제되었습니다.`를 2초간 표시한다.
- 다섯 번째 해제 완료 프레임에서 서버가 즉시 생존자 승리를 확정한다. 별도의 출구 통과나 전원 탈출 판정은 하지 않는다.
- 귀신은 해제 전 탈출구 앞을 막거나 주변에서 열쇠 운반자를 잡을 수 있다.

### 12.3 출구 캠핑 방지

활성 탈출구가 하나뿐이면 귀신이 생존자의 열쇠 운반 동선을 보고 위치를 추론한 뒤 계속 지키는 전략이 생길 수 있다. 기본 방어는 탈출로 데이터 비공개이며, 실제 캠핑 지표가 높을 때만 아래 보조 규칙을 적용한다.

- 활성 탈출로와 후보 좌표는 역할 확정·추격·결과 단계 전체에서 술래 스냅샷과 최초 맵 데이터에 포함하지 않는다.
- 귀신이 탈출구 반경 2.5타일 안에 연속 10초 머물고 반경 6타일 안에 생존자가 없을 때만 `출구 봉쇄`로 판정한다. 실제 추격 중에는 캠핑 누적 시간을 멈춘다.
- 출구 봉쇄가 발동하면 귀신 랜턴이 3초간 깜빡이고 귀신 위치를 생존자 미니맵에 6초간 표시한다.
- 45초 안에 출구 봉쇄가 두 번 발동하면 생존자 전원에게 8초간 이동속도 1.1배를 주어 출구 접근 기회를 만든다. 전투 중인 귀신에게 직접 감속을 걸지는 않는다.
- 다섯 번째 해제 즉시 경기가 끝나므로 열린 출구를 계속 지키는 후반 캠핑은 발생하지 않는다.
- 실제 데이터에서 출구 앞 사망이 과도하면 후보 4개 중 2개를 활성화하고 어느 한 곳에서 5개 열쇠를 소비하도록 확장한다.

### 12.4 은신처 장기 점유 방지

- 한 번의 은신은 최대 25초다. 15초부터 생존자 본인에게 호흡 경고를 표시하고 20초에 귀신에게 방향성 소음을 한 번 전달한다.
- 25초가 되면 자동으로 은신처에서 나오며 2초 동안 다시 숨을 수 없다.
- 같은 은신처에는 나온 뒤 8초 동안 재진입할 수 없다. 다른 은신처로 이동하는 전략은 허용한다.
- 남은 시간이 90초 이하라면 최대 은신 시간을 12초로 줄여 경기가 정체되지 않게 한다.
- 소음은 정확한 캐릭터 좌표가 아니라 은신처가 있는 방향과 대략적인 거리만 전달해 수색 플레이를 유지한다.

## 13. 승패와 결과

- 생존자 팀은 다섯 번째 자물쇠를 해제하는 즉시 팀 승리다.
- 귀신은 모든 생존자를 사망시키거나 제한 시간 동안 자물쇠 5개 해제를 막으면 승리한다.
- 개인 결과에는 `생존`, `사망`, `팀 승리 기여`, `귀신 발견`, `열쇠 발견·운반·자물쇠 해제`, `추격 유지 시간`을 기록한다.
- 귀신 결과에는 `발견 횟수`, `처치 수`, `평균 추격 시간`, `수색 성공`, `탈출 저지`를 표시한다.
- 통신 단절과 앱 백그라운드 전환은 12초 재접속 유예 뒤 봇이 이어받는다. 사용자가 돌아오면 같은 역할과 번호로 제어권을 돌려준다.
- 설정에서 나가기를 두 번 누른 명시적 탈주는 재접속 이탈과 구분한다. 술래의 명시적 탈주는 생존자 승리, 마지막 활성 생존자의 명시적 탈주는 술래 승리로 즉시 종료한다.
- 정상 종료된 승리 팀의 생존자는 100P, 귀신은 150P를 받는다. 패배자와 경기 완료 전에 명시적으로 나간 계정은 포인트를 받지 못한다.
- 승리 포인트는 결과 화면에서 1배로 바로 받거나 보상형 광고 시청 후 2배로 받을 수 있다. 광고 제거 계정은 광고 없이 2배를 받는다.
- 결과 저장과 포인트 수령은 `(match_id, account_id)` 기준으로 멱등 처리해 재접속·연속 탭으로 중복 지급하지 않는다.

## 14. 봇 설계

봇은 사람에게 보이지 않는 전체 정보를 사용하면 안 된다.

### 14.1 생존자 봇

- 자신과 팀이 탐험한 타일만 경로 판단에 사용한다.
- 보이지 않는 열쇠와 탈출구 위치를 미리 알 수 없다.
- 역할을 `탐색`, `열쇠 회수`, `미끼`, `탈출 지원`으로 나눈다.
- 귀신을 발견하면 위험 핑을 보내고 4타일 밖으로 벗어난 뒤 은신처를 찾는다.
- 같은 은신처에 반복해서 들어가지 않고, 다른 생존자의 이동 경로를 완전히 막지 않는다.
- 열쇠를 운반한 봇은 발견된 탈출구로 이동하고, 출구 상호작용을 시작하면 자물쇠 하나를 완전히 해제할 때까지 이동을 멈춘다.
- 열쇠가 없는 봇만 탐험된 지상 열쇠를 목표로 삼으며, 이미 다른 봇이 운반 중인 열쇠나 상호작용 중인 출구를 중복 목표로 선택하지 않는다.
- 다섯 번째 자물쇠가 해제되면 추가 이동 없이 즉시 결과 상태로 전환한다.

### 14.2 귀신 봇

- 랜턴 시야, 소리, 마지막 발견 위치만 사용한다.
- 미탐험 생존자 위치, 열쇠, 팀 미니맵을 읽지 않는다.
- 마지막 발견 위치까지 이동한 뒤 주변 갈림길과 은신처를 우선 수색한다.
- 한 탈출구나 은신처 앞에서 오래 멈추지 않는다.
- 달리기는 발견한 생존자가 2~4타일 사이에 있을 때 우선 사용한다.
- 쉬움 봇은 수색 확률과 소리 반응을 낮추고, 어려움 봇은 마지막 이동 방향을 예측하지만 벽 너머 위치를 직접 추적하지 않는다.

## 15. 화면 구성

### 15.1 생존자 HUD

- 상단: 남은 시간, 탈출구 자물쇠 해제 `3/5`, 내 열쇠 운반 여부, 생존·사망·탈출 번호
- 상단 아래: 접을 수 있는 팀 공유 미니맵
- 우측 하단: 달리기 버튼
- 우측 중단: 생존자 전용 채팅 버튼
- 중앙 시작 카드: `당신은 4번입니다.`
- 발견 상태: 내 캐릭터 머리 위 빨간 느낌표와 화면 가장자리의 짧은 적색 맥박

### 15.2 귀신 HUD

- 상단: 남은 시간, 생존·사망·탈출 인원
- 상단 아래: 귀신 본인이 직접 탐험한 길만 누적되는 전용 미니맵
- 우측 하단: 100초 쿨타임 불켜기 버튼과 60초 쿨타임 달리기 버튼
- 채팅 버튼과 생존자 핑은 표시하지 않으며, 전용 미니맵에도 생존자 위치를 노출하지 않음
- 발견 상태: 귀신 머리 위 빨간 느낌표와 발견한 대상 방향의 짧은 적색 표시

### 15.3 카메라

- 시작부터 결과까지 배율을 고정한다.
- 확대·축소 버튼을 만들지 않고 제스처 입력도 무시한다.
- 캐릭터를 화면 중앙보다 약간 아래에 배치해 진행 방향을 더 넓게 보여 준다.
- 귀신은 랜턴 진행 방향 쪽으로 카메라 중심을 최대 0.8타일 선행시킨다.

## 16. 서버 구조 제안

기존 `GameRoom`은 방 점유, 건설, 포탑, 골드·전력, 스테이지 전투 상태가 강하게 결합되어 있다. 술래잡기는 별도 상태 모델을 사용하므로 기존 엔진에 조건문을 누적하지 않고 전용 Durable Object로 분리한다.

### 16.1 Durable Objects

- `HideSeekRoom`: 초대 코드 하나당 한 객체. 역할, 번호, 위치, 발견, 열쇠, 탐험 비트셋, 채팅 라우팅, 재접속을 관리한다.
- `HideSeekQueue`: 지역·규칙 버전별 대기열 객체. 초기에는 `apac:v1` 하나로 시작하고 동시 접속이 늘면 버킷을 나눈다.
- `HideSeekPresenceShard`: 접속 상태 검색용 샤드. 계정 해시 기준 16개로 분산하고 `idle/lobby/in-game` 상태와 마지막 하트비트를 저장한다.
- 기존 `SocialPresence`: 계정별 WebSocket 푸시에 술래잡기 초대 이벤트를 전달한다. 영속 초대와 수신 차단 설정은 D1을 기준으로 한다.

하나의 전역 Presence 객체에 모든 사용자를 넣으면 병목과 장애 범위가 커진다. 접속 후보 검색은 여러 샤드에서 소수 후보만 표본 추출하고, 방 정원 확정은 항상 해당 `HideSeekRoom`이 최종 판정한다.

### 16.2 상태 흐름

```text
LOBBY
  → ROLE_LOCK (5초)
  → HIDE (20초)
  → HUNT (7분 30초)
  → RESULT
  → CLOSED
```

### 16.3 API 초안

- `POST /api/hide-seek/rooms`: 방 생성
- `POST /api/hide-seek/quick-join`: 참가 가능한 대기실 무작위 참가, 없으면 방 생성
- `GET /api/hide-seek/rooms/{code}/status`: 입장 가능 여부
- `GET /api/hide-seek/rooms/{code}/ws`: 전용 WebSocket
- `POST /api/hide-seek/queue/join`: 역할 선호와 함께 대기열 참가
- `GET /api/hide-seek/queue/status`: 대기·매칭 상태 갱신
- `POST /api/hide-seek/queue/leave`: 대기열 이탈
- `POST /api/hide-seek/rooms/{code}/invite-random`: 유휴 사용자 10~20명 표본 초대
- `POST /api/hide-seek/rooms/{code}/invite-friend`: 친구 초대

Worker가 인증을 확인하고 계정 ID, 외형, 차단·초대 설정을 서버 내부 헤더로 전달한다. 클라이언트가 번호, 역할, 속도, 열쇠 수, 발견 여부를 임의로 정할 수 없어야 한다.

### 16.4 저장 범위

- 방의 실시간 상태는 `HideSeekRoom` SQLite와 메모리 캐시에 저장한다.
- 중요한 상태를 SQLite에 먼저 기록하고 메모리에는 렌더·방송용 캐시만 둔다.
- D1에는 경기 결과, 역할 기록, 명시적 탈주 여부, 승리 보상 수령 배수, 초대 수신 설정, 신고·차단, 보상 정산만 저장한다.
- 채팅은 경기 스냅샷이나 결과에 영구 저장하지 않는다.
- 서버 판정 틱은 20Hz, 역할별 스냅샷은 10Hz, 클라이언트 렌더링은 보간을 사용해 60fps를 목표로 한다.
- 위치 전체 스냅샷과 탐험 비트셋 변화분을 분리해 모바일 트래픽을 줄인다.

## 17. 공정성과 악용 방지

- 귀신과 생존자의 속도·충돌·스킬 쿨타임은 서버가 판정한다.
- 생존자 채팅은 서버가 귀신 소켓을 제외한 뒤 전송한다. CSS로만 숨기지 않는다.
- 자유 채팅과 빠른 문구는 기존 속도 제한을 적용한다.
- 무작위 초대는 수신 거부, 차단, 발신 제한, 방별 중복 방지를 적용한다.
- 게임 중 브라우저가 백그라운드로 이동하면 해당 플레이어를 정지시키지 않고 봇이 임시 제어한다.
- 외형 리소스가 늦게 로드돼도 기본 캐릭터로 즉시 표시하고 충돌 판정은 변하지 않는다.
- 생존자끼리 귀신 사용자에게 외부 채팅으로 위치를 알려 주는 행위는 완전히 막기 어렵다. 결과 데이터에서 비정상적으로 짧은 연속 처치와 반복 파티 패턴을 관찰한다.

## 18. MVP 이후 확장 아이디어

초기 버전에는 핵심 추격과 탈출만 넣고 아래 기능은 실제 지표를 본 뒤 순차적으로 추가한다.

1. `소리 미끼`: 생존자가 한 번만 던져 다른 구역에 발소리를 만든다.
2. `정전 파동`: 90초마다 주변광이 3초간 더 어두워지며 랜턴만 남는다.
3. `보안 카메라`: 사망한 생존자는 고정 카메라 3개만 전환하며 관전하고 채팅은 할 수 없다.
4. `문 잠그기`: 생존자가 한 경기 한 번 문을 3초간 막고, 귀신은 1초 상호작용으로 연다.
5. `귀신 랜턴 꾸미기`: 빛 색상 테두리, 손잡이, 점등 이펙트만 바꾸고 범위는 유지한다.
6. `번호 꾸미기`: 숫자 테두리, 미니맵 핀, 탈출 발자국을 보상으로 제공한다.
7. `주간 변칙`: 열쇠 7개, 랜턴 90도, 거울 복도, 두 개의 탈출 후보처럼 규칙을 하나씩 바꾼다.
8. `연속 3경기 파티`: 첫 경기 뒤 역할을 교대하고 3경기 합산으로 귀신·생존자 양쪽 실력을 비교한다.
9. `관전자 투표`: 결과 화면에서 가장 침착한 생존자, 최고의 추격자, 최고의 길잡이를 익명 투표한다.
10. `연습 모드`: 타이머와 보상 없이 봇 난이도, 맵 시드, 역할을 자유롭게 고른다.

수치형 강화 보상은 넣지 않는다. 포인트, 칭호, 프로필 테두리, 번호 핀, 랜턴·탈출 이펙트처럼 경쟁 성능에 영향을 주지 않는 보상이 적합하다.

## 19. 초기 밸런스 목표

| 지표 | 목표 범위 |
| --- | ---: |
| 귀신 팀 승률 | 45~55% |
| 생존자 팀 승률 | 45~55% |
| 승리 시 생존 인원 | 평균 2~4명 |
| 첫 발견까지 시간 | 45~90초 |
| 평균 경기 시간 | 5~7분 |
| 실제 플레이어 우선 매칭 시간 | 25초 이하 |
| 봇 보충 포함 시작 시간 | 45초 이하 |
| 출구 앞 사망 비율 | 전체 사망의 30% 미만 |
| 같은 은신처 20초 이상 점유 | 경기당 평균 1회 미만 |

귀신 승률만 보고 속도를 조절하지 않는다. 맵 크기, 랜턴 발견 횟수, 출구 캠핑, 모바일 입력 지연, 봇의 정보 치팅 여부를 분리해서 확인한다.

## 20. 구현 단계

### 1단계: 오프라인 규칙 검증

- 전용 맵 생성과 연결성 검사
- 고정 카메라, 암전, 360도·2타일 랜턴, 100초 불켜기
- 한 명의 생존자와 귀신 봇
- 20초 숨기, 접촉 사망, 달리기, 개인당 열쇠 1개 운반, 자물쇠 5회 해제, 탈출구

### 2단계: 전용 실시간 방

- `HideSeekRoom`과 전용 프로토콜
- 0~6번 배정, 역할 선호, 재접속, 봇 인계
- 생존자 전용 미니맵·채팅·핑
- 7개 클라이언트 동시 이동 부하 테스트

### 3단계: 초대와 대기열

- 친구 초대와 8자리 코드
- 지역별 빠른 대기열
- 유휴 사용자 Presence 샤드와 10~20명 무작위 초대
- 초대 수신 설정·차단·속도 제한

### 4단계: 운영과 보상

- 결과·보상 멱등 정산
- 귀신·생존자 승률과 이탈 지표
- 일일·주간 미션 연동
- 꾸미기 보상과 주간 변칙 규칙

## 21. 필수 검증 항목

- 총 7명 입장 시 귀신 1명과 생존자 1~6번이 중복 없이 배정된다.
- 귀신 희망자 충돌과 귀신 봇 대체 규칙이 결정적으로 동작한다.
- 숨기 20초 동안 귀신의 이동·달리기·시야 정보가 잠긴다.
- 기본 랜턴은 벽과 은신처를 통과하지 않고 360도·2타일 안에서만 발견한다.
- 발견 표식은 4타일 밖에서 0.4초 뒤 양쪽 모두 해제된다.
- 술래와 생존자가 6타일 이내면 노란 근접 표식이 나타나고, 생존자의 발소리 음량과 반복 속도가 거리에 따라 단조롭게 증가한다.
- 완전 은신 중인 생존자는 근접 발소리를 듣지만 술래 스냅샷에는 해당 생존자의 위치·근접 상태·발소리 수치가 노출되지 않는다.
- 모든 외형의 기본 이동속도와 충돌 반경이 동일하다.
- 귀신·생존자 달리기 배율, 지속시간, 쿨타임을 서버가 검증한다.
- 불켜기는 반경 7타일을 4초간 서서히 감쇠시키고 발동 시점부터 100초 쿨타임을 서버가 검증한다.
- 빠른 이동 두 틱 사이에서도 귀신 접촉을 놓치지 않는다.
- 귀신 소켓에는 생존자 채팅·핑·팀 미니맵 변화가 전송되지 않으며, 귀신 본인의 탐험 비트셋만 별도로 전송한다.
- 팀 탐험 영역과 1~6번 위치가 재접속 후 복원된다.
- 열쇠 5개가 모두 접근 가능한 위치에 생성되고 탈출구 경로가 연결된다.
- 한 생존자는 열쇠를 하나만 운반하며, 출구에서 열쇠를 하나씩 소비한 다섯 번째 해제 전에는 탈출문이 열리지 않는다.
- 운반자가 일반 접촉 또는 은신처 수색으로 사망하면 열쇠가 정확한 사망 위치에 떨어지고 생존자 미니맵에 회색 사망 표식이 남는다.
- 열쇠 운반 상태와 자물쇠 해제 횟수는 봇 인계·재접속·서버 저장 복원 뒤에도 유지된다.
- 생존자 봇은 출구 잠금 해제 중 이동하지 않으며, 다섯 번째 자물쇠 해제 즉시 생존자 승리 결과 단계로 전환한다.
- 귀신의 통신 단절 후 봇 인계와 재접속 복귀가 경기를 중단하지 않는다.
- 술래와 마지막 활성 생존자의 명시적 탈주가 각각 반대 팀 승리로 즉시 종료되고 정확한 안내 문구를 표시한다.
- 빠른 참가가 참가 가능한 대기실을 무작위로 선택하며, 없을 때 새 방과 정확한 안내 문구를 생성한다.
- 만료·가득 찬 방 초대를 수락해도 다른 방으로 잘못 연결되지 않는다.
- 무작위 초대 수신 거부와 발신 제한이 서버에서 강제된다.
- iOS·Android·웹의 동일한 세로 화면에서 확대·축소가 비활성화되고 달리기 버튼이 안전 영역을 침범하지 않는다.
